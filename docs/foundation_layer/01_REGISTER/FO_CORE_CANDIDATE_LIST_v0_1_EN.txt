THE REGISTER IS ALWAYS OPEN.

The Linux kernel has been patched for decades.
The core is stable not because it is closed —
but because there is discipline at the entry point.

OPEN_REGISTER != CHAOTIC_REGISTER
QUANTITY_OF_FO != QUALITY_OF_REGISTER

------------------------------------------------------------
REGISTER ARCHITECTURE (by analogy with Linux):

CORE_FO (12)
-- the stable core
-- changes slowly
-- only after the full conveyor

SUPPORTING / DOMAIN / DEFERRED
-- modules
-- evolve independently
-- need work before promotion

EMERGENT_FINDINGS
-- the patch queue
-- EF_UNTRIAGED by default
-- go through triage before entering the register

------------------------------------------------------------
MINIMAL ENTRY FILTER for new candidates:

1. Is there a concrete object or observation?
2. Can a formula be stated?
3. Does it not duplicate an existing FO?

If all YES -- it enters as EF_UNTRIAGED.
If not -- it goes back for rework.
